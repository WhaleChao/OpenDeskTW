# OpenDesk TW 2.9.0 品質審查

來源：GitHub v2.8.5，桌面資料夾恢復為 OpenDeskTW。原 main 仍為 2.6.0，因此從最新交付版開始修復，避免倒退。

## 已修復

| 缺失 | 改正與驗證 |
| --- | --- |
| 介面分散、固定深色樣式、缺少明確日夜切換 | 六個工作區、日間／夜間／跟隨系統、設定保留、可搜尋指令、繁中介面；三種尺寸共 18 個工作區檢查無水平溢出 |
| 分頁與鍵盤狀態不完整 | 主功能區及 Word 進階工具加入分頁語意、方向鍵與 Home/End；搜尋方向鍵可循環、Enter 執行 |
| 最近文件或儲存設定損壞會中断啟動 | 資料驗證與安全預設、儲存權限拒絕與容量不足處理；四項測試 |
| PDF 原檔、復原清單及 Word 輸出直接覆寫風險 | 同磁碟暫存完成、同步落盤再原子替換；Windows 替換既有檔案支援；Word 拒絕來源覆寫並備份既有目標 |
| 備份與合併列印撞名 | 隨機備份識別碼、逐次尋找可用合併輸出名稱、重複 split 不覆蓋前次輸出 |
| 復原清單損壞、已關閉工作階段重建快照 | 保留損壞清單、拒絕未受管理快照、復原另存；監視器提交前確認工作階段仍存在 |
| 備份缺乏私有權限 | Unix 0700 目錄／0600 暫存、Windows 使用者／SYSTEM／Administrators 專屬 ACL |
| 大型核心回應使程序管線阻塞、失聯重試重複修改 | 並行讀取 stdout/stderr；修改與含密碼請求不自動重播；後端修改互斥、前端忙碌保護 |
| 安裝版可能意外使用開發資料夾核心 | 正式版優先使用隨附核心，開發 Python 回退需明確環境設定 |
| 長作業阻塞 UI、Windows 背景命令閃出視窗 | 工作移至背景執行；PowerShell／PDF 核心／curl 隱藏背景主控台；Windows 主程式使用 GUI 子系統 |
| PDF 擷取／OCR 丟失保護與文件結構 | 保留加密、 metadata、註解、連結與書籤；OCR 加入隱藏文字層、實際英文字辨識通過 |
| 敏感影像未被永久遮蔽 | Redaction 移除相交影像像素及向量，測試確認文字消失且像素為白 |
| 受限密碼仍可修改、加密 PDF 無法簽署 | 遵守 PDF 權限，owner 密碼可操作；加密增量簽章往返保留密碼且驗證完整 |
| 簽章「完整」被誤當「可信」 | 分開完整性與憑證信任；離線驗證不宣稱已查撤銷狀態 |
| 另存副本失去原始簽章／加密 | 位元組完全相同的原子複製；修改已含簽章文件前提示 |
| 長文字默默省略、頁面範圍部分執行、零位置無效 | 文字放不下即拒絕並保留來源；範圍整體驗證、保留擷取順序及零值設定 |
| PDF 匯出 XLSX 將文字解讀成公式、PPTX 圖片變形 | 試算表文字固定為文字儲存格，投影片保留頁面比例 |
| 資料外送與更新未清楚確認 | MAGI 說明選定文件與模型連線並確認；更新顯示版本與重啟後確認才安裝 |
| Office 封存檔解壓缺乏上限 | 限制項目數、總解壓大小與個別 XML，避免異常文件耗盡記憶體 |
| npm 相依弱點與 CSP 圖片阻擋 | 鎖定更新後 npm audit 零弱點；允許必要資料圖片，禁止 object 與外來 base URI |
| Release 早於驗證公開 | 先建立草稿，兩平台安裝／啟動／復原驗證、Windows 移除、來源包與 Ed25519 更新簽章驗證全部完成才公開 |

## 驗證與交付

- PDF 核心完整往返、安全回歸、四項偏好測試、46 工具／37 操作／7 查詢合約、繁中及 AGPL 封裝檢查。
- Rust 測試涵蓋 Office 結構、合併列印、Word 編修、原子儲存、復原與程序通訊；四項依賴外部引擎／MAGI 的整合測試明確略過。
- 安裝驗證使用自動生成文件與獨立測試設定，不讀取使用者文件。安裝包隨附 PDF 核心 1.4.0-embedded。
- GitHub Release 附各平台安裝驗證、整體發行驗證與 SHA256SUMS；AGPL 對應原始碼包包含此版專案與鎖定 npm／Cargo／Python 上游來源。

## 尚需外部條件的驗收

此版改善已確認缺陷，但不能因此宣稱獲獎或所有商用場景均無缺陷。正式銷售前仍需 Apple Developer ID／公證、Windows Authenticode 憑證、實機印表機及輔助科技驗收、較廣的真實文件相容性測試、第三方授權與商業模式法律確認。PDF 列印目前透過渲染頁面，尚非向量列印保真度認證；Office 深度編輯依賴使用者安裝的 ONLYOFFICE 或 LibreOffice，MAGI 依賴其服務。Awwwards、Webby、FWA 的獎項必須由主辦方實際評審。
